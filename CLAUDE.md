# Tech Wall: video engine

This repo builds the videos for **Tech Wall**, a Facebook page ("Everything tech, pinned to one wall") posting short vertical tech tips for phones, tablets, PCs, consoles and games, in a **Blueprint-style stop-motion** look. **Read `README.md` fully before building anything**: style spec, architecture, timeline API, episode recipe, content rules, posting template, idea backlog.

## Setup (once per session)
```bash
pip install -r requirements.txt        # add --break-system-packages if pip refuses
python3 sharewifi.py 40 200 345        # sanity check: preview frames -> out/frames_sharewifi/
```
`build.sh` uses system `ffmpeg`, or falls back to the `imageio-ffmpeg` binary.
**Host episodes only** (animated presenter, see below): `bash host/setup.sh` once per session (voices + lip-sync, ~450 MB, cached in `~/.cache/techwall-host`, skips what exists).

## Making a new episode
1. **Idea:** if no topic is given, propose 3–4 ideas (rotate devices) with one-line hooks. When the user says "idea first", present the idea + a storyboard table and wait for approval.
2. **Verify** the exact menu path on the official support page (Apple / Google / Samsung / Microsoft / Sony) plus one recent guide. Note OS-version limits and brand differences (the Samsung path goes on the end card). Hooks must be honest.
3. **Format: Host is the DEFAULT (user decision 2026-10-08)** → copy `hostlock.py` on the `host.py` engine (see "Host episodes" below) for every new episode unless the user asks for another style. Use a Blueprint engine only when the user asks for it ("stop-motion", "blueprint", "old style", "motion graphics"), or when the tip can't be shown on a phone (PC, console, TV): then say in the idea message which style it will use and why. **Blueprint stop-motion templates (on request):** copy the closest episode (motion-graphics request → `battery.py` on the `mgfx.py` engine, 30 fps, see README §4). Timeline template: `rf_demo.py` (result-first, see step 5). Screens/props: iPhone → `wifi.py`, Android → `sharewifi.py` / `android.py`, PC → `emoji.py` (or `winv.py`), console → `restmode.py` (give them the result-first opening when copying). File name = episode id (outputs go to `out/frames_<id>/`, `out/audio_<id>.wav`).
4. **Screens:** only those on the path; row ids for everything tapped; fictional data only (network "Home", password "SunnyDays2024", contacts Mom/Sam, example.com).
5. **Timeline (result-first, no title card):** `mb.result_first(t, spec(<result screen>), 'H', '<HOOK>')` so the payoff is on screen at **frame 0** (phone in place, hook caption settled; never a blank blueprint, title card or home-screen tap) → mini scene proving it (≤ 2 s) → hold ~14–20 f → "Here's how" caption + `t.navigate(first screen, back=True)` → one caption per step (hold 3–5 f before each tap) → result caption (hold ≥ 18 f) → bonus → `mb.end_card(t)`; `__main__` = `mb.finish(t, EP, init_props)`. 12 fps, 20–35 s. Frame 0 is the Reel cover (`out/meta_<id>` sets `CF=0`).
6. **Captions** must wrap to ≤ 2 lines: `python3 -c "import themes as th; from lib import wrap; print(wrap('text', th.JB(800,54), 820))"`.
7. **Preview** 8–10 frames, make a contact sheet and actually look at it: captions not truncated, the hand isn't covering key UI (move it away before overlays), screens correct. Then `./build.sh <id>` and spot-check frames from the MP4 and `out/cover_<id>.jpg`.

## Host episodes (animated presenter, format added 2026-10-08)
A 2-D cartoon host (the Tech Wall character: beard, glasses, black T-shirt with the TW logo) stands bottom-left and **speaks the tip** with lip-sync, gestures (welcome / talk / point / front poses) and karaoke captions, while a phone on the right shows each tap. Header = TW logo badge + `TECH WALL` + episode title; end card = full TW logo + FOLLOW. 30 fps, 1080×1920, ~20–35 s. Engine: `host.py` + `host/` (README §4 "Host engine"). **This is the default format for every new episode** (phone tips: iPhone, Android, apps, AI tools on a phone). Idea messages show the storyboard as Host beats: spoken line · caption · pose · screen/taps.
1. Copy `hostlock.py` → `<id>.py`; everything lives in its `SPEC` dict: `title`, `tag`, `tip`, `start` (the **result** screen, shown at frame 0), `screens`, `beats`.
2. **Screens** (`host/screens.js`): `home` (default app grid, tap id `settings`), `list` (iOS-style groups; rows with `id` to tap, `icon`, `color`, `chev`, `value`, `toggle: True/False`, `style` blue/grey/red), `passcode`, `lock`, or `html` (any custom mock; tappable elements carry `data-id`). Generic look-alikes only, fictional data.
3. **Beats** = one spoken line each: `say` (what the voice reads; numbers in words), `cap` (on-screen caption, ≤ 2 lines, auto-shrinks), `pose`, `hook` (beat 0), `step` (drives the STEP n / N chip), `screen` (switch at beat start), `end` (phone out + end card), `do`: actions timed as a fraction of the line: `{'tap': row_id, 'at': .3, 'nav': next_screen, 'back': False}`, `{'nav': screen, 'style': 'fade'|'zoom'|'push'|'pop'}`, `{'type': '258014', 'from': .16, 'to': .42}`, `{'reprompt': True}`, `{'fx': 'confetti'|'thumb'|'lock_close'}`.
4. **Structure (result-first):** beat 0 = hook over the result screen (`start`) → "Here's how" + `screen: 'home'` → one beat per step with taps → result beat (back to the result screen + fx) → `end` beat "Follow Tech Wall for more quick tips!".
5. **Voice:** English default `'voice': 'am_puck', 'speed': 1.08` (Kokoro; other voices in README). **Arabic:** `'lang': 'ar', 'voice': 'kareem', 'speed': 1.3`, `say` = text **with full tashkeel**, `cap` = readable Arabic (captions switch to RTL Cairo font automatically); use the Arabic menu names the user will see. Kareem is CC BY-NC-SA → check before monetizing. TTS + lip-sync are cached per script in `out/host_<id>/`.
6. Preview `python3 <id>.py 0 150 400 …` (frame 0 = the cover: result screen + hook caption, host on screen). Full `./build.sh <id>` takes ~7–8 min for 22 s (Playwright capture, 3 workers). Spot-check the MP4, the cover and that the hand/tap ring land on the right rows.
- Don't edit `host/assets/poses/*` casually: they were hand-fixed (eyes, finger gap, lens, TW shirt) and `host/mouth.js` holds each pose's lip geometry. A new pose needs its mouth entry in `POSE_MOUTH` and `PDEF` in `host/scene.html`.

## Rules
- **Opening (approved 2026-10-03, every future video):** result-first, as in `rf_demo.py`. Frame 0 already shows the payoff with the hook caption; never a blank blueprint, title card or home-screen tap. Target 20–35 s.
- The look must stay **identical** to earlier episodes: navy grid + chalk dims, paper cut-outs with jitter, navy-sleeve hand, yellow dashed tap rings, taped spec captions, stencil titles, synthesized music + SFX. (Host episodes have their own fixed look, defined by `host/scene.html`: keep it identical from one Host episode to the next; their audio is voice + SFX, no music.)
- **Ownership mark (standard since ep. 6):** the Blueprint background carries a chalk `TECH WALL` annotation on the left edge plus `TECH WALL` in the drawing box (`themes.bg_blue`), and the end card ends with a yellow `FOLLOW TECH WALL` strip (`movie_blue.draw_end`, add a pop at `a + 36`). PC episodes: copy `emoji.py` (it reuses the `winv.py` rig and already has the strip, period key, typing hand and taped bursts).
- No brand logos or trademark artwork (the Windows key is labelled WIN, controllers are generic, app screens are generic look-alikes). No real personal data.
- Don't commit rendered output (`out/` is git-ignored). Commit new episode `.py` files.

## Video Library approval loop (`VIDEO_LIBRARY.md`)
Only one row is in progress at a time. **New ideas come once a day at 10:00 Lebanon time (Asia/Beirut)** from the durable Routine "Tech Wall: daily video idea" (`CRON_TZ=Asia/Beirut 0 10 * * *`, fires into this session, survives restarts and closed windows). No other timers: never schedule a `send_later` between ideas. The user is in Lebanon: give every time in Lebanon time.
1. **Daily routine fires (10:00 Beirut)**: `git pull`. If a row is `⏳ Awaiting idea approval`, `🎬 In production` or `👀 Awaiting video review`, stop (reply one line naming the waiting idea, no notification). Otherwise take the **first** `💡 Idea` row, verify the path (step 2 above), set it to `⏳ Awaiting idea approval`, commit + `./sync_main.sh`, and send the user the idea with a storyboard table (Host format by default, see step 3).
2. **Idea approved** → `🎬 In production`, build the episode (steps 3–7), send the MP4 and set `👀 Awaiting video review`. **Rejected** → `❌ Rejected` (or `⏭️ Skipped` if postponed), then go to step 5.
3. **Video approved** → post it as a Reel on the Tech Wall **Facebook page and Instagram (@techwalll)** with `reels.py` by following **`REELS.md`** (`python3 reels.py post out/<id>.mp4 --caption-file /tmp/caption.txt --cover out/cover_<id>.jpg`; VIDEO = `out/<id>.mp4`, COVER = `out/cover_<id>.jpg`, rebuilt with `./build.sh <id>` if the session restarted; CAPTION = the approved README §6 caption; MODE = PUBLISHED; if Instagram fails after Facebook, retry `reels.py instagram` alone), then send it to **TikTok (@techwallz)** with **`TIKTOK.md`** (DRAFT until TikTok audits the app: drafts carry no caption, so send the user the caption to paste and tell them to finish posting in the app), then upload it to **YouTube Shorts (Tech Wall, @techwall0)** with **`YOUTUBE.md`** Part D (`python3 youtube.py upload out/<id>.mp4 --caption-file /tmp/caption.txt --privacy public --thumbnail out/cover_<id>.jpg`; until Google audits the API project the Short lands **private**, so tell the user to switch it to Public in YouTube Studio), fill in **Date published**, set `✅ Published`, commit + `./sync_main.sh`. Report the Facebook, Instagram and YouTube links plus the TikTok and YouTube status. If one platform fails after the others succeeded, still mark the row published, report the failure and retry that platform alone. Changes requested → fix, re-send, stay in `👀`.
4. **Keep `main` current (automatic, never ask):** after *every* commit that touches the library or the repo, run `./sync_main.sh`. It pushes the working branch and fast-forwards `main` to it, so `main` always shows the current library. If `main` is protected and the push is refused, open a pull request and merge it with the GitHub tools instead.
5. **Row finished** (✅ / ❌ / ⏭️) → nothing to schedule: the next idea comes with the next daily 10:00 run. If the user asks for the next idea sooner, send it now.
Never post without both approvals. Act on the user's replies immediately; don't wait for a timer.
Whenever something needs the user (new idea sent, MP4 ready, post published or failed), also send a one-line `PushNotification`.

## Publishing a Reel
All four platforms work the same way: one stdlib Python script each, credentials from the environment (never the repo), a `check` command, and a checklist. Whenever a video has to be posted, follow **`REELS.md`** (`reels.py`: Facebook prepare → start session → upload → publish → confirm → cover, then Instagram container → upload → wait → publish; the raw `curl` steps are its manual fallback), then report both links. Then TikTok with **`TIKTOK.md`** (`python3 tiktok.py draft out/<id>.mp4`; credentials come from the environment, never the repo). Then YouTube Shorts with **`YOUTUBE.md`** Part D (`python3 youtube.py upload ...`; private until Google audits the API project). Use MODE = DRAFT (`reels.py --draft`, `tiktok.py draft`, `youtube.py --privacy private`) for any test. Only publish after the user has approved the video.
**Setup & credentials:** `SETUP.md` (accounts, cloud environment variables + network allowlist, security rules, adding a new page/brand) `TIKTOK.md` Parts A–C (TikTok developer portal, getting tokens, error table) and `YOUTUBE.md` Parts A–C (Google Cloud project, OAuth client, refresh token). Never commit or print secrets: the repo is public.
**Cover:** `build.sh` saves `out/cover_<id>.jpg` (frame 0, the hook, for result-first episodes; the finished title card at frame 70 for the old title-card episodes); `reels.py --cover` (REELS.md) uploads it as the Reel cover and checks it. Never skip it. Look at the cover JPG when spot-checking the build.

- Give a ready-to-paste Reel caption (README §6 template), list the sources used, and suggest the next idea.
